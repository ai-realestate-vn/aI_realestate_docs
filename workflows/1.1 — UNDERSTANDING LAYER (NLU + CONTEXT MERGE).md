# 1.1 — UNDERSTANDING LAYER (NLU + CONTEXT MERGE)

**Mục tiêu:** Hiểu người dùng nói gì và ghép với thông tin đã có.

## 1. Nhiệm vụ chính

1. Nhận câu người dùng
2. Chuẩn hóa văn bản
3. Xác định intent
4. Trích xuất thông tin quan trọng (slots/payload)
5. Đọc short-term memory (STM)
6. Ghép thông tin mới với thông tin cũ (merge rules)
7. Tạo output NLU chuẩn để đưa sang Decision Layer

## 2. Pipeline

### Step 1 — Preprocess

- Chuẩn hóa số: “3 tỷ” → 3_000_000_000
- Chuẩn hóa từ viết tắt: “q7” → “quận 7”
- Chuẩn hóa hướng: “ĐN” → “Đông Nam”

### Step 2 — Intent Classification

**5 intent chính:**

1. `search_apartment`
2. `show_details`
3. `book_appointment`
4. `ask_question`
5. `general_chat`

### Step 3 — Slot Extraction

**Trích xuất:**
Ví dụ với intent `search_apartment`

- số phòng ngủ
- diện tích
- giá bán
- hướng
- khu vực

---

### **Step 4 — Load STM (Short-Term Memory)**

**STM** là bộ nhớ ngắn hạn của phiên trò chuyện hiện tại.
Nó giúp chatbot **không quên** thông tin mà người dùng đã nói ở các lượt trước.

STM chứa:

- **slots:** các thông tin đã thu thập (khu vực, số phòng, hướng…)
- **dialog_state:** trạng thái hiện tại của cuộc hội thoại (collecting, done)
- **missing_slots:** những thông tin còn thiếu để thực hiện tìm kiếm

**Ví dụ STM:**

```json
{
  "slots": {
    "so_phong_ngu": { "min": 2, "max": 2 },
    "huong": "Đông"
  },
  "dialog_state": "COLLECTING",
  "missing_slots": ["gia_ban", "dien_tich"]
}
```

**Ý nghĩa:**
→ Khi người dùng nói thêm: “dưới 3 tỷ”, bot sẽ ghép vào slot cũ.
→ Nhờ STM, bot hiểu người dùng đang tiếp tục yêu cầu trước đó, không bắt đầu lại từ đầu.

---

### **Step 5 — Merge Rules (Ghép thông tin mới + thông tin cũ)**

Mục tiêu: **tạo ra bộ filters hoàn chỉnh** để gửi sang Decision Layer và Qdrant search.

Bot sẽ lấy thông tin từ **câu hiện tại** + **STM** rồi hợp nhất theo 3 quy tắc:

---

**1) NEWEST WINS (thông tin mới nhất được ưu tiên)**

Nếu người dùng thay đổi yêu cầu → bot chọn giá trị mới.

Ví dụ:

```r
“Q7 nhé” → “À không, chuyển Thủ Đức”
```

→ Lưu “Thủ Đức”.

---

**2) Ưu tiên thông tin chắc chắn (Confidence-weighted)**

Nếu câu mới không rõ ràng, bot giữ giá trị cũ.

Ví dụ:

```r
“2 phòng ngủ” → “chắc tầm 2 hay 3 gì đó”
```

→ Giữ 2 phòng ngủ (vì câu mới không chắc chắn).

---

**3) Missing slot vẫn giữ missing**

Nếu câu mới không nhắc đến slot đang thiếu → tiếp tục thiếu.

Ví dụ:
STM đang thiếu `"dien_tich"`
Câu mới: “dưới 3 tỷ”
→ diện tích vẫn thiếu → sẽ được hỏi ở bước sau.

---

**4) Phủ định**
Ví dụ người dùng nói:

“Không q7 nữa, chuyển sang Thủ Đức”

→ Bot phải xoá giá trị cũ trong STM, chứ không chỉ ghi mới.

**Kết quả sau merge**

```json
{
  "so_phong_ngu": { "min": 2, "max": 2 },
  "gia_ban": { "max": 3000000000 },
  "huong": ["Đông"],
  "dien_tich": { "min": 70 },
  "khu_vuc": "Thủ Đức"
}
```

→ Đây chính là dữ liệu **chuẩn** để mapping sang Qdrant query.

---

### Step 6 — Output

```json
{
  "intent": "search_apartment",
  "intent_confidence": 0.92,
  "payload": {
    "filters": {
      "so_phong_ngu": { "min": 2, "max": 2 },
      "gia_ban": { "min": null, "max": 3000000000 },
      "huong": ["Đông"],
      "dien_tich": { "min": null, "max": null },
      "khu_vuc": null,
      "toa": null,
      "tang": null
    }
  },
  "normalized_text": "Tìm cho tôi căn có 2 phòng ngủ hướng Đông"
}
```

-> hỗ trợ mapping sang search ở qdrant

```json
{
  "must": [
    { "range": { "so_phong_ngu": { "gte": 2, "lte": 2 } } },
    { "range": { "gia_ban": { "lte": 3000000000 } } },
    { "match": { "huong": "Đông" } }
  ]
}
```
